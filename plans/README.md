## Historical proposed roadmap (milestones 10+; superseded)

The existing `ROADMAP.md` runs 0–9. Milestone 6 (signed/notarized releases,
self-update, Homebrew cask) stays **blocked on a Developer ID certificate**
and slots in whenever that lands — everything below is independent of it.

### ⭐ TOP PRIORITY — real apps fail to update *(DONE — failures fixed)*

Observed on a real machine (2026-07-16): four apps offered as updates failed
to install — Claude, Dia, Glaze, Raycast. Diagnosed individually (plan 012).
Each root cause was isolated and fixed:

- **Dia** — the appcast lists the full download and its binary deltas as
  sibling `<enclosure>` elements; the parser took the last one (a `.delta`
  Freshly can't apply). Fixed: skip delta enclosures (commit `8baa305`).
- **Glaze & Raycast** — both ship a static `CFBundleVersion` (`0`), so the
  extracted-bundle downgrade check saw equal builds and wrongly blocked a
  real marketing-version upgrade. Fixed: `isDowngrade` compares the clean
  marketing version first, build only as tie-breaker (commit `bd87ff0`).
  Raycast (running, a persistent menu-bar app) also ignored the graceful
  quit; the installer now escalates to force-quit after a grace period so
  the update completes (commit `1696a85`).
- **Claude** — passes the entire verification gauntlet (extract, codesign,
  team, Gatekeeper-notarized); **not a verification bug**. Its 317 MB artifact
  exposed a pathologically slow byte-by-byte download loop. PERF-04 replaced
  it with `URLSession`'s native file-transfer path (commit `8d77769`), and a
  real-app retest completed successfully. See **plan 008**.

### M10 — Correctness & trust polish *(shipped — merged to main)*

Ship confidence: kill the ways Freshly can show a wrong update or leak, and

### M11 — Testable foundation *(plans written for the unblocker; rest specced below)*

Make the app layer verifiable and move orchestration to where it can be
tested, before the codebase grows further.

- Localized-error drift guard in CI → **plan 005** *(shippable now, no
  Xcode-project editing)*. Standing up the app-target test **target**
  (TESTS-01) — adding a unit-test target to `Freshly.xcodeproj` — is a
  maintainer/Xcode task and the precondition for 006.
- Extract scan/install/definitions orchestration from `AppListStore` into a
  `FreshlyEngine` facade, then characterization-test it → **future plan 006**
  (needs the app-target test harness, TESTS-01)
- Schema-versioned, per-record-resilient persistence so an enum rename can't
  silently wipe user history → **future plan 007**
- Performance: cache the parsed Homebrew index across scans; compute the
  five UI sections once per change; memory-map + single-pass artifact
  hashing → **future plan 008**
- Fold the three hand-rolled ETag/cache copies into one `CachedFetcher`
  → **plan 009** *(done; shared decode-before-write cache with dedicated
  conditional-request tests)*

### M12 — Coverage that scales *(direction; spike plans on request)*

Grow the thing the product's whole thesis depends on — catalog breadth —

- `suggest-definition` helper: inspect an installed app and auto-draft its
  definition JSON → **plan 010** *(done)*
- `freshly` CLI (`check --json`) over the already-headless core
  → **plan 011** *(done; read-only, versioned JSON report)*
- Seed more verified definitions (ongoing, contributor-driven)

### M13 — Actionable daily-use surfaces *(direction)*

Close the one-click-short gaps in the features that already exist.

- Notification actions ("Update now") + one-click update from the menu bar
  *(done)*
- "Ignore this app" permanent skip, distinct from per-version skip
- Opt-in beta/prerelease channels (the channel/prerelease signal is already
  parsed and discarded)

### M6 — Distribution *(historical proposal; superseded)*

Signed + notarized CI releases, Freshly self-update via its own appcast,
`brew install --cask freshly`. The dormant pipeline can be built ahead of
the certificate; the certificate is the user's to obtain. The current roadmap
now inserts an unsigned public beta before this signed general-release stage.

## Scoped roadmap entries (future plans)

### 006 — Extract orchestration into a FreshlyEngine facade *(DEBT-02 + TESTS-02)*

`Freshly/AppListStore.swift` (~450 lines) holds source-list assembly with
its precedence tie-break, the remote+bundled definitions merge, and the
brew-vs-direct install routing — all of which `ARCHITECTURE.md` assigns to
`FreshlyCore` ("app target is UI only"), and none of which `swift test` can
reach because it lives in the Xcode app target. Introduce an
`AppUpdateSession` (or similar) facade in `FreshlyEngine` owning source
assembly, definitions merge, and `runInstall`/`runBrewUpgrade`, injected via
protocols so it is unit-testable; the store becomes a thin `@Observable`
view-model. **Do after 005** (needs the test harness). L effort, MED risk —
it touches the app's central control flow; land behind the existing
coordinator tests plus new engine tests for the extracted precedence/merge
policy. Also fixes the RunningApps duplication (DEBT-03: make
`FreshlyInstaller.RunningApps` public and route the brew path through it
instead of the inline reimplementation in `runBrewUpgrade`).

### 007 — Schema-versioned resilient persistence *(DEBT-04)*

`UpdateHistory.load()` and `ScanCache.load()` do an all-or-nothing
`try? JSONDecoder().decode([T].self)`. Because `UpdateRecord` embeds
`SourceID` and `UpdateError.Reason` enums directly, renaming/removing any
case makes the *entire* history array fail to decode and `load()` silently
returns `[]` — wiping user-owned data that cannot be regenerated (the scan
cache self-heals; history does not). Wrap persisted arrays in a
`{schemaVersion, records}` envelope and decode records element-by-element
(skip unreadable ones into an accumulator rather than dropping the file);
add a one-time migration read for the old envelope-less files; document the
enum-evolution rule in `ARCHITECTURE.md`. M effort, LOW risk (additive).

### 008 — Performance: index cache, section memoization, mapped hashing *(PERF-01/02/03)*

Three independent, HIGH-confidence wins, each measurable:
- **PERF-01**: every scan re-parses the multi-MB Homebrew cask index
  (`JSONSerialization` over ~7700 casks) and rebuilds `HomebrewSource`'s
  name/token indices even on an ETag `304`. Memoize the reduced
  `[CaskEntry]` and the built indices keyed on the ETag; skip re-parse when
  unchanged.
- **PERF-02**: `AppListStore.displayStatuses` is recomputed ~17× per
  `ContentView` body eval × ~140 evals per streaming scan. Derive the five
  sections in one pass, memoized, invalidated only when
  `statuses`/overrides/skips change.
- **PERF-03**: the update artifact (100–300 MB) is read fully into RAM via
  `Data(contentsOf:)` — twice when both EdDSA and SHA-512 apply. Map once
  with `.mappedIfSafe` and hash both from that value, or stream the digest.
  (Pairs with the SEC-07 size-cap hardening.)

M effort total, LOW–MED risk. Each has a clean before/after; PERF-02 must
keep `@Observable` invalidation correct.

### 009 — Consolidate ETag/cache into one CachedFetcher *(DEBT-01)*

`HomebrewCatalog`, `GitHubSource`, and `RemoteDefinitionsCatalog` each
hand-roll the same conditional-GET dance (etag file, `If-None-Match`,
`304`→cache read, 2xx→cache write, offline fallback) — and have already
drifted (only `RemoteDefinitionsCatalog` clears a stale etag on a 2xx with
no `ETag` header). Extract one `CachedFetcher.fetch(url:cacheKey:…)` owning
the etag pair, the 304 path, atomic writes, and offline fallback; each
source layers only its own status classification. **Do after 005/006** so
the per-source tests are the safety net. M effort, MED risk (touches every
network path). Fold in SEC-06 hardening (create cache dir `0700`).

### 010 — `suggest-definition` helper *(DIRECTION-01)*

The catalog has **4 entries** and the "community successor to MacUpdater's
database" thesis lives on breadth. Every building block exists: a second SPM
executable is proven (`validate-definitions`), `AppScanner.inspectBundle`
already reads bundleID/name/feed/receipt/Electron manifest,
`HomebrewCatalog` matches cask tokens, and `AppListStore.notCheckable`
already computes the exact set of unsupported apps. Add a
`suggest-definition` executable target that inspects a bundle (or all
unsupported apps), auto-fills what the scanner can read, proposes a cask
token from the index, surfaces both version-key candidates, runs the draft
through `validationProblems()`, and emits a JSON stub for a human to finish
(`githubRepo`/`appcastURL` still need a human — the helper should say so).
Read-only, additive, no install-pipeline impact, no certificate dependency.
M effort, LOW risk. The highest product leverage on the board.

### 011 — `freshly` CLI (`check --json`) — spike *(DIRECTION-02)*

`UpdateCoordinator.checkAll()`, `AppScanner`, and `SourceRegistry` are all
`Sendable` library-level and drive the whole scan with no UI dependency, so
a headless `freshly check --json` (outdated apps + versions + source) is
nearly free and serves the scripting/CI audience MacUpdater's shutdown
stranded. Spike first: define the JSON output schema and decide whether
`install` is in scope (it re-implements the running-app/quit orchestration
that lives in `AppListStore`, so scope to read-only `check` first). MED
confidence on product fit (slightly cuts against the menu-bar-first
positioning) — a maintainer call.

**Implemented 2026-07-25.** `freshly check --json` remains deliberately
read-only. `UpdateCheckReport` is a versioned engine model with deterministic
update/failure ordering; the CLI adds no install path and accepts an optional
GitHub token only through `FRESHLY_GITHUB_TOKEN`.

## Findings considered and rejected (so they aren't re-audited)

- **Homebrew conservative matching** (ambiguous names excluded, `com.apple.*`
  never matches, comma/hex-hash version stripping) — documented, deliberate,
  kills real false positives. Not a finding.
- **JSON files instead of a database**, **whole-file history rewrite per
  append**, **bounded scan concurrency of 8**, **zero third-party
  dependencies**, **un-sandboxed with hardened runtime**, **Mac App Store
  hand-off**, **`.pkg` refused**, **quit interception**, **EdDSA-verified
  team-matched updates skip Gatekeeper** — all documented tradeoffs.
- **Verification gauntlet vs. malicious feed / poisoned definition** — traced
  and confirmed the installer still gates every reachable path; remote
  definitions can only *add* a feed the app lacks and must be HTTPS; invalid/
  future-schema packs are dropped. No finding.
- **Subprocess shell injection** — uses `Process` argument arrays only, no
  `sh -c`, absolute tool paths. Clear.
- **AppcastParser XXE** — `XMLParser` defaults leave external-entity
  resolution off. Safe (optional explicit hardening only).
- **Download filename traversal** — `suggestedFilename` is Foundation-stripped
  and `/`-replaced into `workDir`. Clear.
- **Quarantine removal symlink safety** — uses `removexattr(…, XATTR_NOFOLLOW)`
  after full verification. Clear.
- **Naming/structure drift across the five sources** — they read as one
  family; differing status-classification is legitimate. Not a finding.
- **MenuBarBadgeRenderer / signature-info cost / per-install scanCache save**
  — already memoized / documented-cheap / rare-by-design. Not findings.
- **Issue & PR templates "missing"** — false; they exist under `.github/`.
- **AccentColor empty colorset** (delete or populate the unused colorset) and
  **MenuBar badge cache not clamped to 99+** (clamp the cache key to
  `min(count, 100)`) — real but trivial; **backlog**, not worth their own
  plans. AccentColor deletion touches `project.pbxproj` (accent-color build
  setting), so bundle it with the next intentional project-file change
  rather than a standalone edit.
- **`isSystemInitiatedQuit` / `RunningApps` quit-loop / `SpctlGatekeeper`** —
  system-coupled; the pure `why?` four-char-code and `isRegularWindow`
  predicate are worth extracting+testing (folded into 005's scope note); the
  rest is not worth mocking.
